# KaizenHub — правила проекта

Веб-приложение «Конвейер проектов» (один файл `index.html`, без сборки). Данные и вход — Supabase,
хостинг и серверная функция — Vercel, код и история — GitHub. Пользователь не программист: объясняй
простыми словами, действуй шагами, перед необратимыми действиями спрашивай.

## Структура
- `index.html` — всё приложение (интерфейс и логика). Правим точечно, не переписываем целиком.
- `claude-shim.js` — «переходник»: приложение вызывает `window.claude.use('user' | 'db' | 'sample')`,
  а файл превращает это в запросы к Supabase и к `/api/sample`. Экран входа тоже здесь.
- `config.js` — публичный адрес Supabase и publishable-ключ (их можно коммитить).
- `api/sample.js` — серверная функция Vercel: прокси к Claude (скриншоты, AI-резюме). Проверяет вход и лимиты.
- `supabase/migrations/` — изменения базы. Таблица `docs` хранит «документы» по путям `sp/…`, `inv/…`, `data/users/<id>/…`.
- `tests/` — автотесты (`cd tests && npm install && npm test`).

## Железные правила
1. **Секреты не коммитим.** Нельзя в код, чат и логи: `sb_secret_…`, `service_role`, пароль базы,
   `ANTHROPIC_API_KEY`, токены. Они лежат в Vercel (Environment Variables) и GitHub (Secrets). `.env` в `.gitignore`.
2. **Миграции только вперёд.** Применённый файл в `supabase/migrations/` не правим и не удаляем. Любое изменение базы —
   новый файл `YYYYMMDDHHMMSS_название.sql`. Опасные операции (`drop`, `delete`, `truncate`) — только после явного «да» пользователя.
3. **Права доступа (RLS и функции `doc_set`, `doc_update`, `doc_delete`) меняем осторожно:** после правки пишем/прогоняем
   тест на роли «владелец / участник / посторонний / гость по ссылке». Запись в `docs` идёт только через функции, не напрямую.
4. **Перед пушем** запускаем `tests`. Красные тесты не пушим.
5. **Работаем в ветке**, в `main` — только после проверки на preview-ссылке Vercel. Коммиты короткие, по-русски, по делу.
6. Не добавляем сторонние библиотеки и CDN без необходимости. Скрипты подключаем с точной версией.

## Как выкатывается
- Пуш в ветку → Vercel делает preview-ссылку. Пуш/мерж в `main` → Vercel обновляет боевой сайт.
- Изменения базы: GitHub Actions (`.github/workflows/supabase-deploy.yml`, добавим отдельным шагом) выполняет `supabase db push` при пуше в `main`.
- ВАЖНО: первая миграция `20261020000000_init.sql` уже применена вручную в SQL Editor. Перед включением workflow один раз
  выполнить `supabase migration repair --status applied 20261020000000`, иначе `db push` попытается создать таблицы заново и упадёт.

## Переменные окружения Vercel
`ANTHROPIC_API_KEY`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` (необязательно: `ANTHROPIC_MODEL`, `ANTHROPIC_MODEL_FAST`).

## Известные особенности
- Вход пока по почте и паролю; «Confirm email» в Supabase выключен на время теста. Перед запуском для людей:
  подключить свой почтовый сервис (custom SMTP) и снова включить подтверждение почты. Встроенная почта Supabase шлёт 2 письма в час.
- Удаления Supabase Realtime не присылает: `claude-shim.js` раз в 20 секунд сверяется с базой.
- Лимит запросов к Claude (20 за 10 минут на человека) считается в памяти функции; для жёсткого лимита нужна таблица в базе.
- Данные из версии на claude.ai в Supabase автоматически не переносятся.
